# Mosaic · 角斗士棋

一款支持 **2～4 人**的方块占地策略游戏。选择棋子，从角落出发，通过同色棋子的角连接不断扩张，尽可能少地留下棋子。

支持同屏、在线房间和人机对战，提供中文界面、手机与桌面布局、浅色与深色主题。使用原生 JavaScript 和 Node.js，无需账号，没有 npm 运行依赖。

**[在线试玩](https://djq.duanap.cn/)** · [完整规则](docs/GAME_RULES.md) · [部署指南](docs/DEPLOYMENT.md) · [测试说明](docs/TESTING.md)

## 玩法

| 玩法 | 棋盘 | 颜色与计分 |
| --- | --- | --- |
| 两人双色 | 20×20 | 每人两色，蓝红一方、黄绿一方，合计自己的两色得分 |
| 两人单色 | 14×14 | 每人一色，蓝黄从对角出发，双方交替行动 |
| 三人公共色 | 20×20 | 每人控制一色，公共绿色由三人依次操作，不计入个人得分 |
| 四人个人 | 20×20 | 每人一色，各自计分 |
| 四人组队 | 20×20 | 每人一色，蓝红对黄绿，合计队伍两色得分 |

每种颜色均有完整的 **21 块棋子、89 个小格**。两人单色共 42 块；四色玩法共 84 块。缩小棋盘不会减少每色库存。

每色第一块必须覆盖本色起始角。此后的棋子必须与已有同色棋子**角碰角，不能边贴边**；异色可以贴边，但不能代替同色连接。棋子不能重叠或越界。某色用完棋子或无合法落点时会自动跳过，有棋可下时不能主动跳过回合，可以选择认输。

基础计分按每个剩余小格扣 1 分；奖励计分下，一色全部放完得 15 分，最后放下单格棋子再加 5 分。按个人或队伍总分决定胜负，同分并列。详细规则见游戏内“玩法说明”或[规则文档](docs/GAME_RULES.md)。

## 开始对局

大厅有“同屏玩法、创建房间、加入房间”三个入口。

- **同屏玩法**：在同一台设备上轮流操作，可将其他席位设为标准机器人。
- **创建房间**：选择人数、玩法、计分与回合时限，邀请朋友或添加机器人补齐空位。满员且所有真人在线后，由房主开始。
- **加入房间**：输入朋友提供的六位纯数字房间号，或打开邀请链接。房间号可以包含前导零。

设置使用直接可见的单选框，默认生成随机昵称，也可以手工修改。关闭等候室弹窗仍保留房间，点击“返回房间”可继续；主动退出才释放席位。

### 操作棋子

1. 从棋子区选择一块尚未使用的棋子。
2. 按住棋盘预览的任意实心小格拖动，短按预览可旋转，使用翻转按钮调整镜像。
3. 放到合法位置后，点击打勾按钮确认。松手只固定预览，不会直接落子。

落点提示优先大块，包含旋转与翻转，连续点击可切换不重复方案；提示仍需手动确认。机器人可用于本地或联机对局，无需外部 AI 服务。

| 快捷键 | 操作 |
| --- | --- |
| `R` | 旋转 |
| `F` | 翻转 |
| `T` | 落点提示 |
| 方向键 | 移动预览 |
| `Enter` | 确认落子 |
| `Esc` | 取消选择；弹窗内用于关闭 |

桌面采用玩家、棋盘、操作区三栏布局；手机支持竖屏排列、底部操作栏和短横屏抽屉。玩法说明按主题分区，正文左对齐，提供连接示意图和适应窄屏的卡片布局。

### 保存、悔棋与棋谱

- 最近一次同屏对局自动保存在浏览器，可从首页继续。清除站点数据或禁用存储会影响恢复。
- 同屏支持悔棋；含机器人时，退回最近一次真人行动之前，并撤销其后的机器人落子。联机不支持悔棋。
- 对局结束后可在界面导出 JSON 棋谱，导入后只读回放。新棋谱保存玩法、尺寸、席位与落子来源，兼容旧版 V1/V2 棋谱；早期 14×14 双色记录仍按其原规则读取。

### 联机恢复与计时

联机可选 30、60、90 或 120 秒回合时限。超时后由系统自动放下一块合法棋子；当前回合玩家断线时，最多再等待 45 秒，且不延长原截止时间。

刷新页面可自动尝试重连。关闭标签页后，可在**同一浏览器、同一站点**的首页使用“恢复联机席位”；新标签页不会自动抢占其他页面的席位，同一浏览器可保存多个席位。

恢复记录最多 20 条、每条最多 8 小时，并要求服务端房间及席位仍有效。等候室离线席位在 2 分钟后回收；无人在线的房间在最后一次人工活动 15 分钟后清理。房间在单进程内存中，**服务重启会清空联机房间**。跨浏览器或设备不保证恢复。

## 本地运行

需要 **Node.js 22 或更高版本**：

```sh
git clone https://github.com/duanap/Mosaic.git
cd Mosaic
npm start
```

打开 [http://127.0.0.1:3000](http://127.0.0.1:3000)。运行项目不需要先执行 `npm install`。

| 命令 | 用途 |
| --- | --- |
| `npm start` | 启动 HTTP 服务 |
| `npm run dev` | 监听服务端文件变化并重启；前端修改后刷新页面 |
| `npm run check` | 检查模块语法与浏览器导入路径 |
| `npm test` | 运行原生自动化测试 |
| `npm run verify` | 语法/导入检查、原生测试与构建 |
| `npm run build` | 生成可独立运行的 `dist/` 分发目录 |
| `npm run test:browser` | 运行真实 HTTP/SSE 浏览器回归，需要额外准备 Playwright 和浏览器 |
| `npm run benchmark:bots` | 运行机器人对弈基准 |

浏览器测试依赖与运行参数见[测试说明](docs/TESTING.md)。测试覆盖规则、穷尽搜索、计分、机器人、权限、HTTP/SSE、会话恢复、棋谱、触控与布局。浏览器触屏模拟不等于实体 Android/iOS 验收，机器人基准也不代表对真人的竞技水平。

## 部署

使用**单个 Node.js 主进程**托管房间。公网部署建议让应用绑定回环地址，通过 HTTPS 反向代理对外提供服务；机器人工作线程只负责计算，不维护独立房间。

常用环境配置示例：

```ini
HOST=127.0.0.1
PORT=3000
PUBLIC_ORIGIN=https://game.example.com
TRUST_PROXY=1
```

将 `PUBLIC_ORIGIN` 替换为实际站点来源，不带末尾斜杠。`TRUST_PROXY=1` 仅适用于可信代理覆盖 `X-Real-IP`、应用端口不直接暴露的部署。

`npm start` 不会自动读取 `.env`。需要配置文件时，可复制 `.env.example`，修改后通过以下命令启动：

```sh
node --env-file=.env server/index.mjs
```

反向代理/CDN 对 `/api/*` 应禁用缓存和响应缓冲，保留认证头并允许长时间 SSE 连接。发布时同步更新前端、共享规则与服务端。局域网访问、Nginx/systemd 示例和域名验收步骤见[部署指南](docs/DEPLOYMENT.md)。

## 代码结构

原生 JavaScript ES Modules + SVG + Node.js HTTP + 经认证的 fetch/SSE。客户端只提交落子意图，服务端进行权威判定。浏览器 Web Worker 和服务端有界工作线程池负责提示/机器人计算，对局按状态局部更新，避免重复重建棋盘。

```text
shared/rules.mjs     棋形、规则、尺寸、计分与棋谱
shared/moves.mjs     穷尽合法走法搜索
shared/strategy.mjs  提示排序与机器人策略
server/rooms.mjs     房间、权限、回合、恢复与清理
server/bots.mjs      有界机器人工作线程池
server/index.mjs     HTTP/SSE、请求边界与静态资源
public/             响应式界面、预览操作与分析 Worker
public/rules-ui.mjs  分区玩法说明与连接示意图
public/typography.css 统一字号与组件排版
tests/              原生与浏览器回归测试
deploy/             Nginx、systemd 配置示例
```
